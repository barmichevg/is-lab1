# Исправления от 20 октября 2026

## Что изменено

- **Регистрация в Docker:** сервис `accounts-init` до запуска Payara назначает каталогу аккаунтов владельца UID/GID 1000 и права `0700`, существующему файлу — `0600`. Приложение остаётся непривилегированным. Регистрация проверена с основной конфигурацией Compose: HTTP 201. Существующие хеши аккаунтов сохранились без изменения при пересоздании контейнера.
- **Выбор организаций:** обновление списка сохраняет выбранные ID организаций, координат, адресов и городов. Удалённый ID очищается с сообщением; другой объект автоматически не подставляется. Добавлены регрессии для всех селекторов и ответов, пришедших не по порядку.
- **Целочисленные поля объединения:** дробные Z и ID отклоняются до POST. Сервер тоже проверяет точное преобразование в int. Допустимое объединение проверено через настоящий API.
- **Устаревшая форма:** Organization имеет ORM `@Version`, API возвращает точную строковую `version`. PUT обязан передавать исходную версию. Старое сохранение получает HTTP 409 без изменения БД; черновик и его версия сохраняются в форме. Native addEmployee и перепривязка справочников тоже изменяют версию. Одновременные PUT с одной версией дают один успех и один конфликт.
- **Последняя страница:** после удаления последней строки открывается существующая страница; пустой список показывает `0–0 из 0`, кнопки перехода отключены.
- **Гонки интерфейса:** открытие и фоновое обновление карточки разделены; закрытие, Escape и переход к редактированию инвалидируют старые запросы. Устаревший ответ не открывает карточку заново. Результаты спецопераций отмечают пропущенную инвалидизацию и выполняют GET после снятия busy, не повторяя изменяющий POST.
- **Малый положительный оборот:** форматирование использует значащие цифры; `1e-8` отображается как `0,00000001`. Строковые long по-прежнему форматируются через BigInt без потери точности.

Перепривязка обоих адресов выполняется одним атомарным SQL UPDATE с увеличением версии ровно один раз: это учитывает автоматическое управление `@Version` в EclipseLink.

## Обновление

```bash
mvn clean package
docker compose up -d postgres
./scripts/apply-db.sh
docker compose up -d --force-recreate payara
```

Повторное применение [схемы](../db/schema.sql) обязательно и для существующего тома: оно добавляет version без удаления данных. Открытые вкладки после обновления нужно перезагрузить. Для кафедральной БД используйте [отдельный скрипт](../scripts/apply-db-pg.sh).

В этой среде обычный Maven lifecycle ограничен read-only глобальным кешем и отсутствием сети. Сборка выполнена явными вызовами доступных offline clean/resources/compiler/surefire/war plugins, а не неподтверждённым стандартным `mvn verify`.

Интеграционные тесты выполнены внутри контейнера через временный runner существующих JUnit методов/lifecycle из-за изоляции опубликованных портов. В Chrome использовались реальные HTML/JS и HTTP Payara через временный транспорт; события браузерного WebSocket заменялись контролируемыми вызовами обновления. Настоящий серверный WebSocket проверен отдельно ApiIT. Сквозной тест двух браузеров с настоящим WebSocket не заявляется.

Тестовые доменные записи и временные схемы удалены. Файл аккаунтов до проверки отсутствовал; созданные девять тестовых аккаунтов также удалены после остановки приложения. Контейнеры и тестовый браузер остановлены.
