## Что изменилось

Интерфейс переоформлен как единое приложение **«Реестр»** без переноса на React/MUI и без новых runtime-зависимостей. Бизнес-API, Java-код и SQL этой задачей не менялись. Изменения внесены поверх уже выполненных исправлений, без reset/clean пользовательской работы.

- Общая тёмно-синяя шапка, три постоянных раздела, активный пункт меню, текущий пользователь и выход.
- Светлое рабочее пространство, единая типографика, отступы, кнопки и цвета состояний. CSS страниц собран в [общий файл](../src/main/webapp/app.css), без внешних шрифтов/иконок/CDN.
- Главная страница: заметное создание, отдельная панель фильтра/сортировки, счётчик найденных записей, все атрибуты в таблице, понятные русские подписи, человекочитаемые адреса/типы, числа с разделителями. Название открывает карточку. Поиск по ID выделен в отдельный блок.
- Просмотр, создание, редактирование и удаление по-прежнему в отдельных диалогах. Форма разбита на четыре нумерованные секции: сведения, координаты, официальный адрес, необязательный почтовый адрес. Существующие объекты выбираются по ID и подписи; новые создаются внутри формы. Кнопки сохранения/отмены остаются видимыми при прокрутке.
- Справочники: три подписанные таблицы, якорная навигация, поиск, счётчики найдено/всего; перед удалением показываются связи и обязательный выбор замены, если объект используется.
- Спецоперации: пять отдельных карточек с объяснениями, русскими полями и результатами; порядок enum явно объяснён. У объединения заметное предупреждение о **замене обеих исходных организаций**.
- Вход/регистрация: общий стиль, два режима, подсказки, состояние отправки, проверка повторного пароля и переключение вкладок клавишами стрелок/Home/End. Политика паролей не менялась.
- Доступность: skip-link, landmarks, текущий пункт `aria-current`, имена диалогов, связанные с полями ошибки/`aria-invalid`, таблицы с `scope`, прокрутка таблиц с клавиатуры, явные статусы связи и focus styles. Пустой почтовый индекс не объявляется обязательным.
- На узких экранах содержимое перестраивается в одну колонку. Все столбцы сохраняются: горизонтально прокручивается **сама таблица**, а не вся страница.

### Воспроизведение

Из корня проекта:

```bash
npm ci
npm test
mvn package
```

Необязательная проверка браузера — [ui.browser.test.cjs](../scripts/ui.browser.test.cjs). Нужен Playwright и установленный Chromium/Chrome. Можно использовать внешнюю установку без изменения runtime/dependencies проекта:

```bash
PLAYWRIGHT_MODULE=/absolute/path/to/playwright \
CHROMIUM_PATH=/absolute/path/to/chrome \
node scripts/ui.browser.test.cjs
```

Если Playwright доступен обычному `require('playwright')` и его браузер установлен, обе переменные не нужны. Скрипт **не запускает сервер**: маршруты `127.0.0.1:18089` перехватываются внутри браузерного контекста. Данные демонстрационные; рабочая БД, аккаунты и Helios не затрагиваются. Скриншоты воспроизводимы, но не являются доказательством backend-интеграции.

## Как увидеть изменения в приложении

Готовый артефакт — [is-lab1.war](../target/is-lab1.war). Нужно развернуть новый WAR вместо предыдущего и перезагрузить страницу (при старом CSS — с обходом кэша). Сам редизайн не требует миграции БД. Если на сервере ещё версия **до backend-исправлений от 2 ноября**, для неё также требуется актуальная [SQL-схема](../db/schema.sql), как описано в [HELIOS](HELIOS.md).

**Helios и рабочие контейнеры не изменялись.** Другой сервер вместо существующего приложения не запускался. Это исходники, проверенные изображения и новый WAR, а не заявление, что удалённый сайт уже обновлён.
